### Review Findings

- [x] [Review][Decision] NestJS response envelope not implemented even for scaffold health endpoint — `backend-service/src/app.controller.ts` returns raw `string` from `getHello()`. Dev Notes mark the response envelope as a critical constraint with no exception stated. Decide: (a) add the envelope interceptor now, or (b) explicitly defer to story 1-3 which handles interceptors.
- [x] [Review][Patch] Port conflict — `backend-service` defaults to port 3000, same as `backoffice-web` dev server. Fix: change `process.env.PORT ?? 3000` to `process.env.PORT ?? 3001` in `backend-service/src/main.ts`.
- [x] [Review][Patch] `backend-service` ESLint: `no-explicit-any` is `'off'`, weakening strict TypeScript stance. Fix: change to `'warn'` or `'error'` in `backend-service/eslint.config.mjs`.
- [x] [Review][Patch] `backoffice-web/layout.tsx` has boilerplate metadata: `title: "Create Next App"` and `description: "Generated by create next app"`. Fix: update to ImpactC product copy.
- [x] [Review][Patch] `mobile-client/.claude/settings.json` is an AI IDE artifact committed to the repo. Fix: add `mobile-client/.claude/` to root `.gitignore` and remove the file.
- [x] [Review][Patch] `backend-service/tsconfig.json` missing `"strict": true` — only a manual subset of strict flags present (missing `strictFunctionTypes`, `strictPropertyInitialization`, `useUnknownInCatchVariables`, etc.). Fix: add `"strict": true` alongside or replacing the individual flags.
- [x] [Review][Patch] `useColorScheme()` in `app-tabs.tsx` and `app-tabs.web.tsx` guards against `'unspecified'` but React Native returns `null`/`undefined` — the guard is wrong and can pass `null` to the `Colors` lookup, causing a runtime crash. Fix: guard against `null`/`undefined` instead: `scheme ?? 'light'`.
- [x] [Review][Patch] `mobile-client/tsconfig.json` path alias ambiguity — `@/*` maps to `./src/*` and `@/assets/*` maps to `./assets/*`. TypeScript resolves `@/*` first, so `@/assets/images/...` could resolve to `./src/assets/images/...` (non-existent) instead of `./assets/images/...`. Fix: ensure `@/assets/*` appears before `@/*` in `paths`, or restructure aliases.

## Dev Notes

- **Architecture Compliance**:
  - Keep the projects decoupled in the three distinct directories (`backoffice-web`, `backend-service`, `mobile-client`).
  - Follow the specified naming and project structure patterns outlined in [architecture.md](file:///c:/Users/kahonsu/Documents/GitHub/ImpactC/_bmad-output/planning-artifacts/architecture.md).
- **Critical Quality Constraints**:
  - Always use both `this.log.log()` and `console.log()` for logging the same message.
  - Never remove the `standalone: false` property from the `@Component` decorator if modifying Angular components (though this project uses Next.js/Nest/Expo, this is a global rule to obey).
  - When changing or referencing service names, verify the service exists first and do not assume it's a typo.
  - Rest API response wrapping must envelope successful REST calls in NestJS:
    ```json
    {
      "status": "OK",
      "statusCode": 200,
      "message": "default.message.success",
      "service": "OPTIMIZE-SERVICE",
      "data": { ... }
    }
    ```
- **Project Structure Notes**:
  - Next.js Feature Components: Group feature components under `backoffice-web/src/components/features/[feature-name]/`.
  - NestJS Modules: Group controllers, modules, and services under `backend-service/src/modules/[feature-name]/`.
  - Co-locate unit tests alongside implementation code using `.spec.ts` naming conventions.
